# Gmail — электронные чеки

FingenNext использует официальный Gmail API и OAuth 2.0. Запрашивается только gmail.readonly.

## Что делает импорт

1. Пользователь нажимает «Подключить Gmail и найти чеки».
2. Google показывает стандартный экран согласия.
3. FingenNext получает временный access token.
4. Gmail API ищет письма за последние 90 дней по признакам электронного чека.
5. Для найденных сообщений читаются тема, отправитель и тело.
6. Из письма извлекается итоговая сумма.
7. Создается ImportCandidate с уникальным ключом gmail:<messageId>.
8. Операция остается на проверке пользователя и не попадает в ledger до подтверждения.

Gmail API поддерживает messages.list с Gmail search query и messages.get с format=full. Для этого используется scope gmail.readonly.

## Настройка Google Cloud

Для тестирования приложения необходимо:

1. Создать проект в Google Cloud Console.
2. Включить Gmail API.
3. Настроить OAuth consent screen.
4. Добавить OAuth client для Android с package name FingenNext и SHA-1 сертификата, которым подписан APK.
5. Добавить тестовый Google-аккаунт, если приложение находится в режиме testing.
6. Установить APK и пройти OAuth.

Для production Google требует соблюдать правила OAuth verification. gmail.readonly относится к restricted scopes, поэтому публичная публикация требует отдельной проверки и соблюдения требований Google.

## Почему не используется пароль Gmail

FingenNext не получает пароль от Gmail и не использует IMAP с сохраненным паролем. Доступ предоставляется Google OAuth и может быть отозван пользователем.

## Автоматическая фоновая синхронизация

Текущий релиз выполняет синхронизацию по кнопке. Следующий этап — WorkManager с повторной OAuth-авторизацией без повторного запроса согласия, когда Google возвращает действующий доступ. Если требуется серверный offline access/refresh token, это должно быть отдельным защищенным backend-сценарием; refresh token нельзя встраивать в APK.

## Связь с банковскими операциями

Gmail-чек не создаёт отдельную финансовую операцию автоматически. Он должен сопоставляться с банковским кандидатом по:

- сумме;
- дате/времени;
- продавцу;
- валюте.

При совпадении источники объединяются в одну покупку.
