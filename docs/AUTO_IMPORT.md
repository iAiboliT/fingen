# Автоматический импорт FingenNext

## Назначение

FingenNext не должен безусловно превращать внешние сообщения в финансовые операции. Внешний источник сначала создаёт ImportCandidate, после чего пользователь подтверждает или отклоняет его.

Источники:

- банковские уведомления Android;
- Mir Pay, если оно публикует доступное уведомление;
- QR/электронный чек;
- Gmail через официальный OAuth;
- в будущем OCR и другие провайдеры.

## Банковские уведомления

Используется NotificationListenerService. Доступ включается пользователем в системных настройках Android. Сервис извлекает сумму, направление и исходный текст, после чего сохраняет кандидата локально.

Система не читает произвольные уведомления для создания операций: парсер требует финансового контекста или известного финансового приложения.

## Поступления

Каждое распознанное поступление показывается пользователю с вопросом:

- зарплата;
- возврат долга;
- оплата услуг;
- продажа/оплата покупки;
- возврат денег;
- перевод;
- подарок;
- другое.

Если в FingenNext есть активный долг «Мне должны» с точно совпадающей суммой, поступление получает предложение «Возврат долга». Если сумма меньше остатка долга, пользователь может выбрать соответствующий долг вручную.

После подтверждения возврата долга создаётся DebtRepayment, а остаток долга уменьшается атомарно вместе с записью операции.

Для обычного дохода создаётся Income.

## Расходы

Для внешнего расхода пользователь выбирает счет и категорию. После подтверждения создаётся обычная Expense.

В дальнейшем правила категорий должны обучаться по исправлениям пользователя.

## Дубликаты

Каждый внешний кандидат имеет уникальный sourceKey. Повторное событие того же уведомления не должно создавать второй кандидат.

## Принцип источника истины

Внешние источники являются входными данными. Источником истины после подтверждения остается Financial Engine и его ledger.

## Gmail

Gmail подключается только через официальный OAuth Google и с минимально необходимым scope. Для чтения текста электронных чеков потребуется gmail.readonly; этот scope относится к restricted scopes и требует соблюдения требований Google OAuth verification для публичного приложения.

Интеграция Gmail должна использовать тот же ImportCandidate pipeline, что и банковские уведомления. Она не должна напрямую записывать транзакции.

## ФНС

Официальный Open API проверки чека ККТ требует регистрации внешнего пользователя и мастер-токена ФНС. Поэтому нельзя подменять его неофициальным вызовом без полученного ФНС доступа.

Архитектура ReceiptProvider отделяет провайдера от финансового ядра. После получения официального доступа ФНС добавляется как FnsReceiptProvider, а сторонний провайдер остается резервным источником.

## Безопасность

- данные кандидатов хранятся локально;
- банковские уведомления не отправляются на внешний сервер;
- токены внешних сервисов не зашиваются в APK;
- пользователь сам включает Notification Listener;
- операция не проводится без подтверждения пользователя.
