# Проверка чеков ФНС и пользовательская авторизация

## Что выяснено по состоянию на 27.09.2026

Официальное «Открытое API проверки чека ККТ» ФНС предназначено для внешних пользователей-разработчиков. ФНС определяет внешнего пользователя как организацию или ИП-разработчика. Для подключения подается заявка, после чего ФНС выдает мастер-токен.

Пользователь FingenNext не должен получать этот мастер-токен.

## Production-схема

Правильная схема для публичного приложения:

FingenNext Android
→ HTTPS backend FingenNext
→ FNS Open API

Мастер-токен хранится только на backend и никогда не попадает в APK или DataStore телефона.

Android передает backend только данные фискального QR и получает нормализованный чек.

## Почему не делать токен в приложении

Мастер-токен является ключом разработчика и должен защищаться. Если положить его в APK, его можно извлечь. Кроме того, ФНС прямо возлагает на внешнего пользователя ответственность за сохранность мастер-токена.

## Пользовательский путь без токена

Для обычного пользователя остаются:

1. QR-чек — FingenNext получает QR камерой.
2. Электронный чек по Gmail — пользователь дает FingenNext официальный OAuth-доступ только на чтение Gmail; чек импортируется как кандидат.
3. Банковское уведомление/SMS — сумма и направление импортируются как кандидат.
4. Пользователь может самостоятельно зарегистрироваться в «Мои чеки онлайн» по номеру телефона и получать там свои чеки.
5. Если пользователь использует «Мои чеки онлайн», FingenNext не должен просить пароль или SMS-код ФНС и не должен имитировать внутренний API сервиса.

## «Мои чеки онлайн»

ФНС предоставляет пользователю авторизацию по номеру телефона и хранение чеков, поступивших по телефону/email или добавленных через QR. Официальной документации на публичный API для сторонних мобильных приложений для доступа к истории конкретного пользователя найдено не было.

Поэтому автоматизировать вход через скрытые endpoint/captcha или reverse engineering нельзя считать production-интеграцией.

## Рекомендация для FingenNext

Сделать три уровня:

- FNS Backend Provider — основной production-провайдер;
- Gmail/банковские уведомления — пользовательские источники без токена ФНС;
- Third-party Receipt Provider — резервный/тестовый источник.

Для пользователя экран настроек не должен показывать поле «API-токен ФНС». Оно допустимо только в отдельном developer/self-hosted режиме.
